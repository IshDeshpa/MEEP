Reading the comparisons

World size changes the number of tiles and the two world-buffer sizes. It does not change the per-tile geometry or the LUT size. Doubling X and Z gives four times as many tiles. Per-tile counters remove this work-volume effect so that transition and material differences stay visible.

Keep these distinctions in view. Independent face/edge LUT loads remain volatile so all six/twelve lookups execute. Cube/sequential loads are ordinary cached loads. Mode comparisons therefore include cache-policy and instruction differences. L1/L2 hit rates cover the whole kernel (world buffers and LUT, including writes), rather than isolated LUT accesses. DRAM bytes come from hardware counters. Warp instructions are warp-level counts, not per-thread instruction counts.

Measurement context

How this sweep was measured
  • NVIDIA GeForce RTX 2070, 36 SMs, 8 GiB VRAM, 4 MiB L2. CUDA 12.6, -O3 C++17, sm_75. No explicit shared-memory staging. One launched thread per tile, padded to blocks of 256.
  • Worlds: X×200×X for X = 500, 600, 700, 800, 900, 1000. Material counts: 8, 10, 12, 14. Tile count is (X/2)×(200/2)×(X/2).
  • Native timing: five samples of ten whole-world ticks, after two warmup ticks. Each sample first preheats the GPU for at least 500 ms, then restores the seeded world before the warmup/timed sequence. CUDA graphs reduce host submission gaps. CPU reference calculation, allocations, initialization, transfers, preheating, and comparisons are outside the timed event interval. Every final output tile is CPU/GPU checked after every native sample.
  • Hardware profiling: five warmed ticks, ordinary direct launches, application replay, cache-control none, clock-control none. The profiler selects only the timed update kernel, skipping warmups and excluding the separately named preheat and initialization kernels. The source timing is preserved; instrumented event times are diagnostics. Replay reuses the native verification instead of repeating the expensive CPU reference.
  • Raw counts are averaged per complete tick, then divided by tile count where indicated. Cache percentages use the sum of hit sectors divided by the sum of hit + miss sectors. Other percentages are means across profiled ticks. Missing counters appear as unavailable, not zero.
  • Each world/material case passes live VRAM checks. Required allocations and current free/used VRAM are saved with the measurements. Case order is deterministically shuffled (seed 42); each sample starts from the same seeded initial state. GPU display activity and clocks are not externally locked.
  • This is a fixed-partition scheduling/LUT experiment. The rules are deterministic synthetic permutations. There are no shifted Margolus partitions, cross-tile interactions, rendering, or physical material rules; different update variants need not implement equivalent automata.
